# ProofRail Quickstart

This guide verifies the public evidence package from a clean repository
checkout. It does not require GitHub credentials, a wallet, cloud
infrastructure, or access to a production database.

## 1. Create A Clean Environment

Requirements:

- Python 3.11 or newer
- a POSIX shell

```bash
git clone <repository-url> proofrail
cd proofrail
python3 -m venv .venv
.venv/bin/python -m pip install .
```

Confirm the entry points:

```bash
.venv/bin/proofrail --help
.venv/bin/proofrail-server --help
```

## 2. Reproduce The Portable Proof

```bash
.venv/bin/proofrail reproduce examples/reproduce_artifact/
```

Expected:

- process exit code `0`
- top-level `"valid": true`
- every listed check has `"passed": true`

The verifier checks the signed manifest, file hashes, authority signatures,
valid and invalid permits, consumed-once state, ledger, checkpoint, trust
checkpoint, external anchor, validation-report hash, and expected tamper
failure.

## 3. Break The Artifact

```bash
cp -R examples/reproduce_artifact /tmp/proofrail-tampered
printf '\nchanged by evaluator\n' >> /tmp/proofrail-tampered/TRANSCRIPT.md
.venv/bin/proofrail reproduce /tmp/proofrail-tampered
test "$?" -eq 4
```

Expected:

- the verifier reports `"valid": false`
- the declared file hash check fails
- the process exits `4`

Use a fresh destination if `/tmp/proofrail-tampered` already exists.

## 4. Run The Full Test Suite

```bash
PYTHONWARNINGS=error \
  .venv/bin/python -m unittest discover -s tests -v
```

Expected for v0.7:

- 70 tests pass
- no warning is accepted

The suite includes permit replay, signature mutation, role escalation, ledger
rewrite, false reconciliation, external anchoring, database state drift,
wrong-instance migration, path replacement, cross-database SQL expansion, and
post-consumption failure handling.

## 5. Run The GitHub Authority Demo

```bash
demo_dir="$(mktemp -d)"
.venv/bin/proofrail demo github-merge-authority --out-dir "$demo_dir"
.venv/bin/proofrail ledger verify "$demo_dir/proofrail-ledger.jsonl"
.venv/bin/proofrail ledger verify "$demo_dir/tampered-ledger.jsonl"
test "$?" -eq 4
```

This demo is credential-free and does not contact GitHub. It generates a valid
ledger, signed checkpoint, public verification key, tampered ledger, and
transcript.

## 6. Inspect The Second Domain

Run only the database migration authority tests:

```bash
.venv/bin/python -m unittest \
  tests.test_database_migration_authority -v
```

Review:

- `proofrail/migration.py`
- `integrations/openclaw/database_adapter.py`
- `schemas/database_migration_permit.schema.json`
- `docs/SECOND_EXECUTION_DOMAIN.md`

The test database is temporary. No production database is opened or changed.

## 7. Regenerate Deterministic Evidence

```bash
out="$(mktemp -d)"
.venv/bin/python scripts/generate_validation_report.py \
  --out "$out/VALIDATION_REPORT.md" \
  --evidence-out "$out/validation-results.json"
diff -u VALIDATION_REPORT.md "$out/VALIDATION_REPORT.md"
diff -u validation-results.json "$out/validation-results.json"
```

No diff means the human-readable and machine-readable validation evidence
regenerated byte-for-byte.

## What This Proves

Passing this quickstart proves that the repository's published evidence is
replayable in your environment and that the included controls behave as
tested.

It does not prove:

- independent authorship
- external key identity
- production readiness
- correctness of buyer-authored policy
- correctness of application data after a schema migration
- security against compromise of enough trusted signing or observation keys

Continue with `docs/KNOWN_LIMITATIONS.md`, `docs/TRUST_BOUNDARIES.md`, and
`docs/OPEN_STANDARD_DIRECTION.md` to evaluate those boundaries.
